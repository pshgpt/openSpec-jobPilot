# Proposal

## Why

The match report lists every requirement as matched or a gap, but leaves the reader to work out what it means overall: is this a good fit, and which gaps actually matter? A short summary of the analysis answers that at a glance. It completes the "summary" step from JobPilot's original idea, scoped as a summary of the analysis for the candidate, not a pitch to an employer.

## What Changes

- Every report with at least one requirement gains a **summary** with two parts:
  - **Facts, written by code:** the list of missing must-have requirements and the list of missing nice-to-have requirements, taken from the verified report.
  - **Verdict, written by the LLM:** a few sentences on the overall fit, generated by a third LLM call that sees only the verified report. It contains no match percentage, since the score is shown separately and comes from code.
- If the verdict call fails, the run still succeeds. The report and the facts are printed, the verdict is marked unavailable, and a warning goes to standard error. **BREAKING (behavior):** this makes an exception to the rule that an analysis failure prints no report.
- The text report shows a "Summary" section under the score. The JSON output gains a `summary` field. **BREAKING (output format):** the JSON object has a new field, and the empty case becomes `{"score": null, "requirements": [], "summary": null}`.
- When no requirements are found, there is no summary and no verdict call.

**Out of scope:** a tailored application summary or cover letter aimed at employers (a possible later change), and changes to extraction, matching or scoring.

## Capabilities

### New Capabilities
- `analysis-summary`: Summarizes a finished analysis: code-generated lists of missing requirements plus an LLM-written verdict, with rules that keep the verdict consistent with the verified report, and a fallback when the verdict can't be generated.

### Modified Capabilities
- `analysis-cli`: The text report and JSON output include the summary, and a failed verdict no longer fails the whole run.

## Impact

- Code: a new summary module, `src/analyze.js` (one more pipeline step), `src/report.js` (text and JSON rendering), `src/cli.js` (warning on standard error), and their tests.
- One more Gemini API call per analysis that has at least one requirement, so slightly higher cost and run time.
- Anything that reads the `--json` output sees the new `summary` field.
